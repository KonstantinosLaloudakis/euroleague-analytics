# Pace Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a Pace page (20 seasons of possessions per 40 minutes: league trend, every team raw and opponent-adjusted, playoffs vs regular season, pace vs winning, extreme games) plus a Pace card on the Team Deep-Dive page.

**Architecture:** A new analyzer `game_pace.py` plugs into the existing one-pass game-records engine (`calculate_game_records.py` over `pbp_games.iter_games()`), computes per-game possessions, aggregates them per season and team, and writes `docs/data/current/pace.json`. Pure frontend helpers in `docs/pace-core.js` (unit-tested with `node --test`) feed two consumers: the new `docs/pace.html` + `docs/pace.js`, and a card in `docs/team.js`.

**Tech Stack:** Python 3 + pandas (pipeline), pytest; vanilla JS + Plotly 2.27 (CDN), `node --test`.

**Spec:** `superpowers/specs/2026-11-18-pace-page-design.md`

## Global Constraints

- Possessions per team = FGA + 0.44 × FTA − OREB + TOV, with FGA codes `2FGM 2FGA 2FGAB 3FGM 3FGA 3FGAB LAYUPMD LAYUPATT DUNK`, FTA codes `FTM FTA`, OREB `O`, TOV `TO`.
- Game possessions = mean of both teams; pace40 = possessions × 40 / minutes; minutes = 40 + 5 × overtimes.
- Overtimes: `PERIOD` max ≤ 4 → 0; else `max(1, round((max MINUTE − 41) / 5))`; without a usable `MINUTE` column, `max(1, number of 'BP' rows with PERIOD ≥ 5)`.
- Regular season = phases `RS` + `TS`. Playoffs = `PO` only. Champion = winner of the season's highest-gamecode `FF` game.
- All floats in `pace.json` rounded to 2 decimals.
- No hardcoded season years in Python scripts (`tests/test_no_hardcoded_season.py`); current season comes from `season_config.CURRENT_SEASON`.
- Team names/colours only from `docs/constants.js` (`TEAM_NAMES`, `teamInk`, `getTeamColor`); charts use `PLOTLY_THEME` / `PLOTLY_CONFIG`; data loads via `fetchJSON`.
- New page uses the shared nav: `<nav class="site-nav" id="site-nav" aria-label="Main"></nav>` + `<script src="nav.js"></script>`.
- Tests: `.venv/Scripts/python.exe -m pytest tests/ -q` and `node --test tests/js/*.test.js` must both pass at the end of every task.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Season with no regular-season games yet** (pre-season, `current_season` has no rows): the Pace page and team card show the latest season that has data, labelled with its season, never blank or `NaN`. Pinned by `latestSeason` test in Task 4.
2. **Team with no previous season** (new clubs such as Dubai 2025-26, Besiktas 2026-27): its row shows only this season's dot, no line. Pinned by `seasonTeams` test in Task 4.
3. **Multi-overtime games** (the feed calls every OT period 5): a 4OT game scales by 60 minutes, not 45. Pinned by `test_four_overtimes_scale_by_sixty_minutes` in Task 1.
4. **Old shot codes** (2008-09 to 2014-15 `LAYUPMD`/`LAYUPATT`/`DUNK`) count as field-goal attempts. Pinned by `test_old_shot_codes_count_as_attempts` in Task 1.
5. **`pace.json` missing or unloadable**: the Pace page shows an error message; the team page hides its Pace card and everything else on it still works. Pinned by the browser check in Task 6.

import sys

        + ev('B', '2FGM', n=24) + ev('B', '3FGA', n=5) + ev('B', 'TO', n=2)

    if minute is not None:

    return pg.clean_game(df)


def test_possessions_formula():

### Task 4: Frontend helpers `pace-core.js`

**Files:**

**Interfaces:**
- Consumes: `pace.json` arrays `league`, `teams`.
- Produces `window.PaceCore`, also exported with `module.exports` in the same pattern as `docs/player-links.js`:
  - `latestSeason(teams) -> number | null`: the highest season that has team rows.
  - `paceStreak(league) -> { streak: number, base: row | null, latest: row | null }`: the count of trailing consecutive season-on-season increases in `pace`. `base` is the row before the streak and `latest` is the last row. Input order doesn't matter.
  - `seasonTeams(teams, season, metric) -> rows`: `metric` is `'pace'` or `'adj_rel'`. Returns that season's rows sorted by `metric` descending, each with `prev` set to the same team's `metric` the previous season, or `null`.
  - `teamHistory(teams, league, team) -> [{ season, pace, league }]`: ascending, the team's seasons only, with that season's league pace.
